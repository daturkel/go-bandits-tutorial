Go A hands-on course

Learn Go by building a bandit service

One project, fourteen chapters and a capstone, with a short primer to start. It starts as a command-line simulation of a multi-armed bandit and grows into replicated gRPC microservices, picking up the language and the backend patterns exactly when the project needs them.

How the course works

A multi-armed bandit repeatedly chooses one of several options (an ad, a model variant, a ranking), observes a reward, and has to balance trying things it is unsure about against repeating what already works. That decision loop is small enough to fit in a few hundred lines and rich enough to need everything a Go backend uses: interfaces, testing, concurrency, HTTP, persistence, metrics, and finally state that has to stay consistent across replicas.

  • You write the interesting parts. Each chapter has a start folder, the last chapter's finished project with the key pieces removed, and a solution folder next to it. The page explains the tasks in order, the tests tell you when a task is done, and hints and answers sit behind a click. (Chapters 1 and 2 use this format so far; the rest are still being converted and ask you to build the project by following the listings.)
  • Every listing is real. Code on these pages is pulled from solutions/chNN, which compiles and passes go test -race. Terminal output comes from running it, with fixed seeds.
  • Each chapter is a complete snapshot. cd solutions/ch05 && go test -race ./... works without anything else. Lines a chapter adds are marked in the margin of its listings.
  • Everything has tests. Tasks and exercises come with tests that fail until you implement them; reference answers sit under a fold on the page.

You need Go 1.27 or newer. Start with Primer, or read the README for how to run any chapter.

Part I: Language core

  1. 01Modules, packages, first simulationSet up a Go module and write an epsilon-greedy bandit simulation that prints its regret.
  2. 02Interfaces and methodsIntroduce the Policy interface, add UCB1, and swap policies without touching the runner.
  3. 03Errors, tests, benchmarksMake failure explicit with error values, then pin behaviour down with table-driven tests, golden files and benchmarks.
  4. 04Generics and the comparison harnessAdd Thompson sampling, write generic helpers where they earn their place, and chart regret across many seeds.

Part II: Concurrency

  1. 05Goroutines and channelsRun simulations in parallel with fan-out and fan-in.
  2. 06Shared stateMutexes, atomics and the race detector: see a real race, then fix it.
  3. 07Context, select, worker poolsCancellation, timeouts and bounded worker pools without goroutine leaks.

Part III: Serving

  1. 08net/httpServe select and reward endpoints with JSON, middleware and httptest.
  2. 09Structure and operationsProject layout, configuration, structured logging and graceful shutdown.
  3. 10Persistence and delayed feedbackStore bandit state and pending selections; handle rewards that arrive late or never.
  4. 11Observability and performancePrometheus metrics, pprof, a load generator and one real bottleneck.

Part IV: Distributed

  1. 12Why naive replicas break the banditWatch replicas diverge, then fix it with mergeable counts and measure the cost of staleness.
  2. 13Splitting into servicesProtobuf and gRPC: a policy service, feedback ingest and an aggregator.
  3. 14Running the systemDocker, Compose, load balancing, and a Python client for the Go service.

Capstone

  1. ★End-to-end load testCompare policies across replicas with staleness, and decide where to go next.
