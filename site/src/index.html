Go A hands-on course

Learn Go by building a bandit service

One project, fourteen chapters and a capstone, with a short primer to start. It starts as a command-line simulation of a multi-armed bandit and grows into replicated gRPC microservices, picking up the language and the backend patterns exactly when the project needs them.

How the course works

A multi-armed bandit repeatedly chooses one of several options (an ad, a model variant, a ranking), observes a reward, and has to balance trying things it is unsure about against repeating what already works. That decision loop is small enough to fit in a few hundred lines and rich enough to need everything a Go backend uses: interfaces, testing, concurrency, HTTP, persistence, metrics, and finally state that has to stay consistent across replicas.

  • You build it yourself. From chapter 1 on, the project is your own directory and your own git repository, and every chapter adds to the code you wrote in the one before. (Chapters 1 to 4 work this way so far; the later chapters are being converted and ask you to follow their listings instead.)
  • Each chapter gives you tests and a spec. You copy in the chapter's tests and new files, and the page explains each task: what it is for, what it must do, and the library calls it needs. Hints and answers sit behind a click. Many tasks change code you already wrote, the way real work does.
  • You cannot get lost. Every chapter has a reference solution. If you fall behind, copy it over your project and carry on; git diff shows what was different.
  • Everything is real. Every listing on these pages comes from code that compiles and passes go test -race, and every output was produced by running it, with fixed seeds.
